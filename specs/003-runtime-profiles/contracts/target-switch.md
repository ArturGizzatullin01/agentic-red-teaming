# Контракт: утилита смены target (003) — исправлено по R2

**Created**: 2026-09-06. R2: apply+мгновенный restore не доживает до кампании —
утверждён интерфейс **операторского wrapper**: apply → readback → sanity → ЗАПУСК
переданной команды кампании → restore в finally. Утилита остаётся вне core и Attack.

## Интерфейс

```text
scripts/set_stand_target.py <oss120|oss20|glm> --stand-path <path-to-compose-project> \
    -- <campaign command и аргументы...>
```

- Целевые профили — данные профиля, не hardcoded ветки ядра.
- Wrapper — операторский инструмент: не вызывается атаками и runner'ом; campaign
  запускается как дочерний процесс с текущей моделью.
- `# TODO PROBE`: режим явных apply/restore с токеном состояния (для длинных
  сессий оператора) — отложен; в 003 строится только wrapper.

## Протокол wrapper

1. Прекондишены: compose-проект существует, занятые порты выявлены, ключи по именам
   ENV.
2. Сохранить исходный профиль (именованный бэкап, не общий `.env.bak`).
3. Apply профиля (base_url/model/ключ по имени ENV) + recreate agent-api.
4. **Readback** фактической конфигурации без секретов → SwitchRecord. Readback
   недоступен или mismatch с запрошенным → **блокировка режима**: кампания НЕ
   запускается, restore выполняется, exit 1.
5. Health-check → непустой sanity (длина ответа, не содержимое). Пустой sanity →
   кампания не запускается, restore, exit 1.
6. **Запуск дочерней команды кампании** через subprocess; exit code кампании
   фиксируется.
7. **Restore в finally** (успех ИЛИ сбой кампании).

## Коды возврата и две ошибки

- Кампания успешна, restore успешен → exit = exit code кампании.
- Кампания упала, restore успешен → exit = exit code кампании (ошибка кампании не
  маскируется).
- Restore упал → **exit 1 независимо от исхода кампании**; stderr содержит ОБЕ
  ошибки (кампании и restore) и фактически оставшееся состояние стенда. Грязное
  состояние важнее честного негатива.

## Тесты (fake process runner + fake HTTP, без реального Docker)

- Fake campaign наблюдает НОВУЮ модель; после него (включая падение кампании)
  восстановлена СТАРАЯ.
- Readback mismatch / unavailable → кампания не стартует, restore выполнен, exit 1.
- Пустой sanity → кампания не стартует, restore выполнен, exit 1.
- Restore-fail виден и не подменяет exit кампании, кроме случая restore-fail
  (см. таблицу выше).
- Каждая операция ровно один раз; занятый порт выявлен до apply; отсутствие ключа
  ENV — ошибка до apply.
