# Контракт: выбор ролей и запуск пресета

Дата: 2026-09-06. Статус: проектирование по запросу пользователя, код не реализован.
Расширяет [spec](../spec.md) и [plan](../plan.md); конституцию не меняет.

## Пользовательский сценарий

Локальная панель запуска показывает два селектора: «Атакующий», «Модель стенда»,
и фиксированное поле «Судья: DeepSeek». Рядом — сценарий атаки, число попыток,
seed и кнопка «Запустить». Уточнение пользователя 2026-09-06 заменяет выбор судьи:
во всех runtime-пресетах используется настроенный профиль DeepSeek v4 Flash.
Над полями расположены сохранённые пресеты. Нажатие пресета заполняет все три поля;
«Запустить» проверяет конфигурацию и запускает кампанию без редактирования YAML.
Дополнительный запуск по одному нажатию — кнопка «Запустить» непосредственно на
карточке сохранённого пресета: она использует показанные сценарий и бюджет попыток.
Выбор карточки сам по себе не меняет работающий стенд и не делает сетевой запрос.

| Пресет | Атакующий | Судья | Модель стенда |
|---|---|---|---|
| Основной | Qwen | DeepSeek | GPT OSS 20B |
| Перестановка | GPT OSS 20B | DeepSeek | Qwen |
| Большой стенд | Qwen | DeepSeek | GPT OSS 120B |

Названия обозначают желаемые профили. Фактические endpoint/model URI берутся
из конфигурации и проверяются; доступность назначения модели стендом пока неизвестна.
Одна модель может занимать несколько ролей одновременно. Это не конфликт настройки.
Контексты, инструкции и клиенты ролей изолированы; история атакующего не передаётся
судье как управляющая инструкция. Совпадение моделей судьи и стенда отражается
в отчёте как свойство эксперимента, а не блокирует запуск.

## Профили и сохранение

Развести ModelEndpoint (провайдер, endpoint, model URI, ссылка на ENV), RoleBinding
(роль, endpoint, версия инструкции, параметры генерации) и LaunchPreset
(три привязки ролей, schema_version, идентификатор). В реализации это dataclass,
согласованные с RoleProfile/ResolvedConfig, без дублирующих независимых систем типов.
Инструкция судьи хранится в привязке роли DeepSeek, отдельно от инструкций атакующего
и стенда. Переключение пресета не изменяет профиль или инструкцию судьи.

Пользователь может изменить атакующего или стенд и выбрать «Сохранить как пресет».
Профили не содержат значений ключей. В UI — понятные названия, URI в деталях.
Транспорт без права переопределения системной инструкции должен использовать
отдельного настроенного агента для каждой роли; это проверка возможностей,
а не обещание, что один облачный agent ID подходит для всех ролей.

Единый resolver обслуживает CLI и панель. Приоритет: явный выбор поля UI/CLI,
затем выбранный пресет, затем scenario, затем default. После разрешения создаётся
неизменяемый снимок конфигурации запуска; изменение формы влияет только на следующий run.
Static attacker и deterministic-only judge остаются доступными offline-режимами.
Offline означает отсутствие вызова LLM-судьи, а не подмену DeepSeek другой моделью.
В runtime-конфигурации явный иной judge в CLI/scenario/импортированном пресете
отклоняется до запуска с понятной ошибкой; молчаливое исправление запрещено.
Недоступность DeepSeek не включает другого LLM-судью. Применяется контракт judge bridge:
недоступная оценка остаётся UNKNOWN, а preflight config error блокирует запуск.

## Модель и стенд — разные сущности

Выбор Qwen в поле стенда означает замену LLM внутри того же memory/tool-стенда,
а не отправку запросов непосредственно в chat API Qwen вместо стенда.
Сохраняются адаптер, память, инструменты и пользовательские границы сценария.
Совместимость endpoint с tool calling и протоколом стенда проверяется отдельно.
Если такая замена недоступна, пресет показывается недоступным с конкретной причиной;
тихий fallback на 20B, mock или прямой chat endpoint запрещён.

## Жизненный цикл запуска

Состояния: выбран → проверяется → стенд подготавливается → выполняется →
восстанавливается → завершён/ошибка/отменён. Запуск остаётся активным до restore.

1. Разрешить роли, сценарий и бюджет; проверить ENV без вывода значений.
2. Получить эксклюзивное право на изменение общего стенда. Занятый стенд —
   понятный отказ или явная очередь; две кампании не переключают его одновременно.
3. Через существующий проектируемый wrapper сохранить конфигурацию, применить
   target, выполнить readback, health и sanity. Не писать Docker-логику в core/UI.
4. Запустить кампанию на проверенной модели. Неподтверждённый readback блокирует её.
5. После успеха, ошибки или отмены восстановить исходную конфигурацию и проверить
   восстановление. Сбой restore виден отдельно от результата атаки.

Панель не исполняет произвольную shell-строку пользователя: использует типизированный
запрос запуска и аргументы процесса. Двойное нажатие не создаёт два запуска;
«Остановить» инициирует отмену с cleanup. Панель локальна по умолчанию, без публикации.
Это управляющий интерфейс; алгоритмы Attack/Adapter/Runner/Oracle/Reporter не дублируются.

## Воспроизводимость и критерии приёмки

В provenance сохраняются preset ID/hash, три requested/resolved модели,
версии инструкций, эффективные параметры, seed, scenario/candidate hashes,
способ проверки модели стенда и факт использования каждой роли.
Выбранный, но не вызванный judge помечается inactive, а не «проверил результат».
Секреты не сохраняются. Пресет не заменяет provenance фактического выполнения.

- Fake transport доказывает обе пользовательские комбинации с DeepSeek в роли судьи.
- Смена атакующего не меняет судью/стенд; смена стенда сохраняет его инструменты/память.
- Несовместимость, отсутствующий ключ, mismatch readback не допускают reset/delivery.
- UI и CLI дают одинаковый ResolvedConfig при одинаковом выборе.
- Проверены двойной клик, занятый стенд, отмена и ошибка восстановления.
- Offline default работает без сети; live-проверки выполняются отдельным gate.
- Атакующий и стенд переключаются независимо; runtime-судья всегда DeepSeek.
- Чужой judge в CLI/scenario/пресете отклоняется; fallback на другую модель отсутствует.

Перед реализацией обновить clarify/analyze фичи и выбрать минимальный UI-стек
по существующему окружению. Этот документ не означает, что кнопки уже реализованы.
