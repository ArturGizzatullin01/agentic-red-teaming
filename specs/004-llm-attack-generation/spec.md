# Feature Specification: LLM-генерация атак и многоуровневая эскалация

**Feature Branch**: `004-llm-attack-generation`

**Created**: 2026-09-06

**Status**: Draft

**Input**: User description: "Прикрутить ллмку для генерации промптов и атак. Во-первых, для
фичи с многоуровневостью — добавить в CLI опцию включения. Во-вторых, если агент не
инвестиционный, данных нет — атаки должны генерироваться (по универсальному описанию, что должна
делать атака) под конкретный формат конкретного агента любого назначения. Выбор: сгенерировать
атаки заранее (отдельная cmd, переиспользуемо для похожих агентов) или генерировать в онлайне
(атакующая LLM адаптирует каждый запрос по ответу защищающегося, до предела, например 5 попыток)."

## Обзор

Сегодня инструмент проверяет только один класс целей — инвестиционного агента: атаки написаны
руками под его формат (поля `cus`, портфели клиентов), а payload'ы фиксированы в коде паков
`attacks/`. Как только безопаснику нужно проверить **другого** агента (поддержка, HR-ассистент,
агент обработки заявок), данных нет: наши payload'ы говорят на языке инвестиционного стенда и в
чужой агент не попадают.

Фича закрывает две связанные потребности:

1. **Генерация атак под произвольного агента.** По декларативному описанию цели (её назначение,
   роли, инструменты, формат ввода, что считать утечкой) атакующая LLM порождает конкретные
   payload'ы и триггеры под формат этого агента — из наших универсальных описаний классов атак
   (memory poisoning, cross-user, scope escalation и т.п.).

2. **Многоуровневая эскалация.** Сначала используется заранее сгенерированный корпус атак (дёшево
   и воспроизводимо). Если атака не пробила защиту, включается онлайн-уровень: атакующая LLM
   переписывает атаку по ответу защищающегося и пробует снова, до предела попыток. Переход на
   онлайн-уровень управляется отдельной CLI-опцией.

Разграничение precompute vs online даёт пользователю экономический выбор: заранее сгенерированный
корпус переиспользуется на всех похожих агентах и оплачивается один раз, а дорогая онлайн-адаптация
включается точечно там, где статики не хватило.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Заранее сгенерировать переиспользуемый корпус атак под нового агента (Priority: P1)

Безопаснику нужно проверить нового агента (не инвестиционного). Он описывает цель в файле-профиле
(назначение, роли/инструменты, формат ввода, признаки утечки и внешнего последствия) и запускает
отдельную команду генерации. На выходе — сохранённый, версионируемый корпус атак под формат этого
агента, собранный из наших универсальных описаний классов атак. Корпус можно переиспользовать для
других агентов того же типа без повторной оплаты генерации.

**Why this priority**: Это ядро фичи и единственная часть, снимающая текущий блокер «для не-
инвестиционного агента нет данных». Даёт самостоятельную ценность даже без онлайн-уровня: корпус
можно прогонять существующим `run`/`campaign`. Дешевле и воспроизводимее онлайна.

**Independent Test**: Дать файл-профиль тестового агента и офлайн-заглушку атакующей LLM
(детерминированную, без сети) → команда генерации создаёт корпус атак в заданном формате; корпус
проходит те же структурные проверки, что и рукописные паки, и прогоняется через `run` на mock-
таргете, давая честный вердикт (`success` или `NOT_EXPLOITABLE`).

**Acceptance Scenarios**:

1. **Given** валидный файл-профиль агента и доступная атакующая LLM, **When** пользователь
   запускает команду генерации корпуса, **Then** создаётся сохранённый набор атак под формат этого
   агента, каждая атака помечена своим классом (family) и силой сигнала, и набор пригоден для
   последующего прогона без повторной генерации.
2. **Given** уже сгенерированный корпус под агента типа «поддержка», **When** пользователь
   указывает его для похожего второго агента, **Then** корпус переиспользуется без повторных
   вызовов атакующей LLM.
3. **Given** профиль без обязательного поля (например, не задан признак внешнего последствия),
   **When** запускается генерация, **Then** команда завершается ошибкой конфигурации (код возврата
   как у сбоя настройки) с понятным сообщением, а не молча генерирует бесполезный корпус.

---

### User Story 2 - Онлайн-адаптация: добить атаку, которую не взял корпус (Priority: P2)

Пользователь прогоняет атаки против агента, и часть из них не пробивает защиту. Он включает
онлайн-уровень: по ответу защищающегося агента атакующая LLM переписывает не сработавшую атаку и
пробует снова, до предела попыток на атаку. Как только атака пробила защиту (или исчерпан лимит
попыток и бюджет), эскалация по этой атаке останавливается.

**Why this priority**: Повышает найденность там, где статический корпус слеп, но дороже и
недетерминирована. Осмысленна только поверх готового корпуса (US1), поэтому P2.

**Independent Test**: На mock-таргете с офлайн-заглушкой атакующей LLM, которая на первой попытке
даёт заведомо не срабатывающий payload, а на второй — срабатывающий: с выключенным онлайн-уровнем
атака честно помечается `NOT_EXPLOITABLE`; с включённым — тот же вход приводит к успеху со второй
попытки, и число попыток не превышает заданного предела.

**Acceptance Scenarios**:

1. **Given** атака, не пробившая защиту, и включённый онлайн-уровень, **When** раннер получает
   ответ защищающегося, **Then** атакующая LLM формирует следующую попытку с учётом этого ответа, и
   попытка выполняется как новая атака того же класса.
2. **Given** включённый онлайн-уровень и предел попыток N, **When** ни одна попытка не пробила
   защиту, **Then** число попыток по этой атаке не превышает N, атака помечается `NOT_EXPLOITABLE`,
   и это не считается сбоем инструмента (код возврата успешного прогона).
3. **Given** онлайн-уровень **выключен** (по умолчанию), **When** атака из корпуса не пробила
   защиту, **Then** переформулировок не происходит и результат совпадает с прогоном без этой фичи.
4. **Given** исчерпан бюджет вызовов атакующей LLM, **When** остаются непройденные атаки, **Then**
   эскалация корректно прекращается, факт исчерпания бюджета фиксируется в отчёте, а уже полученные
   результаты не теряются.

---

### User Story 3 - Включить онлайн-эскалацию флагом CLI (Priority: P2)

Пользователь одной опцией CLI управляет тем, работает ли прогон только на заранее сгенерированном
корпусе (уровень 1) или при неудаче поднимается на онлайн-уровень (уровень 2) с заданным пределом
попыток и бюджетом.

**Why this priority**: Это управляющая обвязка US2 — без неё онлайн-уровень нечем включить. Мелкая
по объёму, но обязательная для сдачи US2, поэтому тот же приоритет.

**Independent Test**: Один и тот же сценарий и таргет прогоняются дважды — с флагом и без; без флага
поведение и стоимость совпадают с текущим инструментом, с флагом включается онлайн-уровень и предел
попыток берётся из опции.

**Acceptance Scenarios**:

1. **Given** прогон без флага онлайн-эскалации, **When** атака не пробила защиту, **Then**
   онлайн-уровень не активируется (поведение по умолчанию — только корпус).
2. **Given** флаг онлайн-эскалации с явным пределом попыток, **When** атака не пробивает защиту,
   **Then** число попыток ограничено этим пределом, а не значением по умолчанию.

---

### User Story 4 - Отчёт объясняет, какая атака как была получена и сколько попыток заняла (Priority: P3)

В отчёте по прогону для каждой находки видно её происхождение: рукописный пак, заранее
сгенерированный корпус или онлайн-адаптация; для онлайновых — сколько попыток заняло пробитие и
исчерпан ли бюджет.

**Why this priority**: Прозрачность источника и стоимости важна безопаснику для доверия к отчёту,
но она надстройка над US1–US3 и на MVP не блокирует.

**Independent Test**: После прогона со смешанными источниками атак отчёт содержит для каждой находки
происхождение и (для онлайновых) число попыток; агрегат по прогону показывает суммарную стоимость
генерации/эскалации.

**Acceptance Scenarios**:

1. **Given** прогон, где часть атак из корпуса, а часть добита онлайн, **When** собирается отчёт,
   **Then** у каждой атаки указан источник, а у онлайновых — число попыток до успеха или до предела.

---

### Edge Cases

- **Атакующая LLM недоступна** (нет ключа, сетевая ошибка, таймаут, лимит): генерация корпуса и
  онлайн-эскалация — это сбой соответствующей операции (код возврата сбоя), но он должен быть отделён
  от честного «атака не пробила защиту». Уже собранные результаты не теряются.
- **Атакующая LLM порождает невалидную атаку** (не соответствует формату агента, пустой payload,
  отказ модели): такая попытка отбраковывается и не засчитывается как проведённая атака; при онлайн-
  эскалации отбраковка расходует попытку и фиксируется.
- **Профиль агента неполон или противоречив**: генерация не запускается, ошибка конфигурации.
- **Онлайн-эскалация зациклилась** без прогресса (модель повторяет один и тот же не срабатывающий
  payload): предел попыток и бюджет — жёсткий стоп; бесконечного цикла быть не может.
- **Совпадение моделей**: если атакующая модель совпадает с моделью цели или с моделью судьи, это
  наследует слепые пятна — конфигурация должна как минимум явно это фиксировать (предупреждение),
  чтобы результат не читался как независимая проверка.
- **Сгенерированный корпус применяют к агенту другого типа**, чем тот, под который он собран:
  допустимо (переиспользование), но происхождение и целевой профиль корпуса должны быть видны, чтобы
  не выдать нерелевантный прогон за релевантный.
- **Недетерминированность онлайна**: повтор прогона может дать другой путь эскалации; это принимается
  как свойство уровня, но seed/пределы должны делать поведение настолько воспроизводимым, насколько
  это возможно для LLM.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Инструмент ДОЛЖЕН принимать декларативное описание цели (файл-профиль агента),
  включающее как минимум: назначение агента, его роли/инструменты, формат ожидаемого ввода и
  признаки того, что считать компрометацией — утечкой данных и внешним последствием.
- **FR-002**: Инструмент ДОЛЖЕН по файлу-профилю и универсальным описаниям классов атак порождать
  конкретные атаки (payload доставки + триггер активации) в формате, пригодном для данного агента.
- **FR-003**: Каждая сгенерированная атака ДОЛЖНА нести те же атрибуты, что и рукописная (класс
  атаки/family, сила сигнала, ожидаемый эффект), чтобы прогоняться существующим пайплайном без
  правок ядра.
- **FR-004**: Инструмент ДОЛЖЕН предоставлять отдельную команду CLI для **заблаговременной**
  генерации корпуса атак и сохранения его в переиспользуемом виде.
- **FR-005**: Сохранённый корпус атак ДОЛЖЕН быть переиспользуем для других агентов без повторной
  генерации, и его происхождение (под какой профиль собран) ДОЛЖНО быть зафиксировано вместе с ним.
- **FR-006**: Инструмент ДОЛЖЕН поддерживать многоуровневый режим: сначала атаки из заранее
  сгенерированного корпуса; при неуспехе — онлайн-уровень с адаптацией атакующей LLM.
- **FR-007**: На онлайн-уровне атакующая LLM ДОЛЖНА формировать следующую попытку с учётом ответа
  защищающегося агента на предыдущую попытку.
- **FR-008**: Онлайн-эскалация по одной атаке ДОЛЖНА быть ограничена настраиваемым пределом попыток
  (по умолчанию — конечное разумное число, например 5) и останавливаться при первом успехе.
- **FR-009**: Инструмент ДОЛЖЕН предоставлять опцию CLI для включения/выключения онлайн-уровня; по
  умолчанию онлайн-уровень ВЫКЛЮЧЕН (поведение совпадает с текущим — только корпус/рукописные паки).
- **FR-010**: Онлайн-уровень ДОЛЖЕН уважать бюджет вызовов атакующей LLM и при исчерпании бюджета
  корректно прекращать эскалацию, сохраняя уже полученные результаты.
- **FR-011**: Инструмент ДОЛЖЕН честно разделять исходы: сбой генерации/атакующей LLM (код возврата
  сбоя) ≠ атака не пробила защиту (успешный код возврата + finding `NOT_EXPLOITABLE`).
- **FR-012**: Невалидная сгенерированная атака (не соответствует формату, пустой/отказной ответ
  модели) ДОЛЖНА отбраковываться и не засчитываться как проведённая атака.
- **FR-013**: Отчёт ДОЛЖЕН показывать происхождение каждой атаки (рукописный пак / заранее
  сгенерированный корпус / онлайн-адаптация) и для онлайновых — число попыток до успеха или до
  предела.
- **FR-014**: Отчёт ДОЛЖЕН отражать стоимость: число вызовов атакующей LLM и факт исчерпания бюджета
  (по аналогии с тем, как это уже делается для судьи).
- **FR-015**: Атакующая LLM ДОЛЖНА конфигурироваться отдельно от модели цели и модели судьи; при
  совпадении моделей инструмент ДОЛЖЕН как минимум явно предупреждать о наследовании слепых пятен.
- **FR-016**: Секреты (ключи атакующей LLM) НЕ ДОЛЖНЫ попадать в файлы конфигурации/профили —
  только имена переменных окружения, как это уже принято для судьи и identities.
- **FR-017**: Новые классы атак и режимы генерации ДОЛЖНЫ подключаться конфигом/файлами, без правок
  ядра (Runner/Oracle/composite остаются нетронутыми).
- **FR-018**: Многоуровневый режим ДОЛЖЕН оставаться проверяемым офлайн (детерминированная
  заглушка атакующей LLM), чтобы e2e проходил в CI без сети и ключей.

### Key Entities *(include if feature involves data)*

- **Профиль агента (Agent Profile)**: декларативное описание проверяемой цели — назначение, роли/
  инструменты, формат ввода, признаки утечки и внешнего последствия. Вход для генерации; не содержит
  секретов. Переиспользуется между похожими агентами.
- **Описание класса атаки (Attack Class Spec)**: универсальная, агент-независимая формулировка того,
  что атака должна сделать (например «протащить чужую инструкцию в глобальный слой памяти и добиться
  её применения к другому пользователю»). Вход для генерации; сопоставляется существующим family.
- **Сгенерированный корпус атак (Generated Attack Corpus)**: сохранённый переиспользуемый набор
  конкретных атак под формат конкретного профиля, с зафиксированным происхождением (какой профиль,
  какие классы, какой генератор). Выход команды генерации; вход для прогона.
- **Попытка онлайн-эскалации (Escalation Attempt)**: одна итерация онлайн-уровня — переформулированная
  по ответу защищающегося атака, её номер в пределах лимита и исход. Часть трассы/отчёта прогона.
- **Атакующая LLM (Attacker LLM)**: сконфигурированная отдельно модель-генератор атак, с собственным
  бюджетом вызовов; отлична от модели цели и модели судьи.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Безопасник может сгенерировать пригодный к прогону корпус атак под нового
  (не инвестиционного) агента, имея только его файл-профиль — без написания payload'ов вручную.
- **SC-002**: Один и тот же сгенерированный корпус применяется как минимум к двум разным агентам
  одного типа без повторной оплаты генерации.
- **SC-003**: При выключенном онлайн-уровне поведение и стоимость прогона неотличимы от текущего
  инструмента (нет вызовов атакующей LLM во время прогона, результат идентичен).
- **SC-004**: При включённом онлайн-уровне атака, которую статический корпус помечал как
  непройденную, но которая пробивается адаптацией, пробивается в пределах заданного лимита попыток;
  число попыток по любой атаке никогда не превышает лимит.
- **SC-005**: Сбой атакующей LLM никогда не выдаётся за «атака не пробила защиту» и наоборот
  (исходы различимы по коду возврата и типу finding в 100% случаев).
- **SC-006**: Многоуровневый e2e-сценарий проходит в CI полностью офлайн (без сети, ключей, Docker)
  на детерминированной заглушке атакующей LLM, доказывая и успех, и честный `NOT_EXPLOITABLE`.
- **SC-007**: По отчёту для любой находки однозначно определяется её происхождение и (для
  онлайновых) число потраченных попыток и факт исчерпания бюджета.
- **SC-008**: Существующие 12 тестов остаются зелёными; ядро (Runner/Oracle/composite) не изменено.

## Assumptions

- Многоуровневость трактуется как каскад: **уровень 1** — заранее сгенерированный корпус (дёшево,
  воспроизводимо), **уровень 2** — онлайн-адаптация по ответу защищающегося (дороже, включается
  флагом). Это следует из ответа пользователя «сначала генерация заранее, если не получилось —
  онлайн-вариант».
- Основной режим генерации — **гибрид**: precompute как ядро + онлайн как опциональный слой за
  флагом (выбор пользователя).
- Описание цели задаётся **файлом-профилем** (не свободным текстом в CLI и не авто-probe живого
  агента) — выбор пользователя. Авто-probe формата с живого агента — вне рамок этой фичи (кандидат
  на будущее).
- Атакующая LLM реализуется **отдельным новым клиентом**, не завязанным на модуль судьи (`judge/`),
  хотя может следовать тем же проверенным паттернам (OpenAI-совместимый HTTP, `api_key_env`, ретраи,
  бюджет вызовов).
- Универсальные описания классов атак берутся из существующих family проекта (`cross_user_bac`,
  `direct_poisoning`, `scope_escalation`, `false_precedent`, `tool_argument_hijack`) и/или из
  референс-базы атак команды; собственно новый расширяемый реестр «описаний классов» — деталь плана.
- Инвестиционный агент и его рукописные паки остаются рабочими и не переспецифицируются задним
  числом (brownfield-правило конституции).
- Онлайн-уровень применяется к переформулировке payload'а/триггера атаки; классический пословный
  jailbreak-пинг-понг адаптируется к жизненному циклу памяти (обратная связь появляется на стадии
  триггера/retrieval, а не при записи в память).
- Пределы по умолчанию: лимит попыток онлайн-эскалации — конечное разумное число (ориентир 5, как в
  описании пользователя); бюджет вызовов атакующей LLM задаётся конфигом по аналогии с судьёй.
- Стоимость «крутой» генерации ограничена бюджетом (ограничение из `description_interim.md`):
  precompute-путь существует именно чтобы не платить за онлайн там, где это не нужно.
