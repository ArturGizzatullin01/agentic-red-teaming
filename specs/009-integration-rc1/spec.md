# Spec: 009 — интеграционный release candidate RC1 (подготовка к R1/C10)

Карточка описывает сборку ОДНОГО локального release candidate из уже принятых слоёв.
Она НЕ заменяет MASTER-PLAN и не создаёт второй очереди: статусы задач ведутся
только в `docs/integration-handoff/MASTER-PLAN.md`.

## Требования

- **FR-1 Стартовая точка.** Ветка `integration/full-stack-rc1` начинается ровно на
  `03832ee`, если подтверждена линейность
  `origin/main(6f0c4a7) → b1926e0 → c7fd325 → 052467c → 03832ee`.
  Никакой реконструкции стека cherry-pick'ами. Принятые ветки, `team-publish` и
  `main` не меняются.
- **FR-2 Границы слоёв.** Каждый слой подтверждается на финальном дереве узкой
  профильной проверкой (его собственные тест-файлы), а не четырьмя полными
  прогонами suite. Фиксируется: SHA, набор файлов дельты, ключевые контракты,
  существующий ACCEPT, отсутствие отменяющего более позднего коммита.
- **FR-3 Интеграционные инварианты.** Сквозной поток
  scenario → ExperimentSpec → GoalContract → run/campaign → AttemptRecord →
  BudgetLedger → EvidenceBundle → report/replay → CLI-результат проверяется
  матрицей существующих тестов по именам. Новый тест добавляется ТОЛЬКО при
  реальном дефекте: красный минимальный тест → минимальный фикс → зелёный →
  отдельный коммит. Косметический рефакторинг запрещён.
- **FR-4 C10 wheel-gate.** По `specs/007-evidence-foundation/offline-install-gate.md`:
  сначала только известные интерпретаторы и локальные кэши. Если setuptools/
  wheelhouse недоступны — подэтап помечается NEEDS_AUTHORITY с одной точной
  PowerShell-командой, скачивание без разрешения запрещено; остальные этапы
  продолжаются. Установка считается доказанной только из wheel в чистый venv
  вне репозитория с `--no-index`; запуск через PYTHONPATH проверкой не является.
- **FR-5 Release manifest.** Один чеклист: base/candidate SHA, порядок слоёв,
  коммиты, diff-stat, профильные проверки, один полный suite, результат C10,
  известный непроходной промежуточный коммит CLI (C5 `39458fa`), выбранная
  стратегия истории, отсутствие секретов/мусора, точная команда будущего
  fast-forward/PR, rollback-точка, какие статусы MASTER-PLAN можно обновить.
  `acceptance.md` не помечает merge выполненным; `main` нигде не становится ✅.
- **FR-6 Запреты.** Без push, merge/ff в main, force-push/reset --hard, live-target,
  Mongo, платных вызовов, P09-live/PROMO2024-live, P11/P13/P14/P15, новых family,
  изменений Runner/Oracle/composite ради зелёности, самостоятельных статусов
  ACCEPTED/MERGED/LIVE_VERIFIED.
- **FR-7 Следующая работа.** P09-full остаётся незапущенным; готовится только
  offline-handoff: что можно начать после R1, что нужно адаптеру и владельцу
  стенда, какие live-бюджеты утверждает пользователь, минимальный live-пак
  (один smoke + один negative control), затем отдельная атака PROMO2024.

## Критерии готовности

STATUS READY_FOR_REVIEW возможно, если: линейность подтверждена; профильные
проверки всех четырёх слоёв зелёные на candidate SHA; матрица инвариантов
сведена к существующим тестам; полный suite прогнан ОДИН раз; C10 либо пройден,
либо точно заблокирован с командой для снятия блокера; manifest заполнен.
